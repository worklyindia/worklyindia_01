Overview
Workly India works as an OAuth 2.1 / OpenID Connect identity provider.
Your website gets the user's id, email and profile after they press Allow on the Workly India consent screen.
Uses Authorization Code + PKCE. Supported scopes: openid, email, profile, offline_access (refresh token).
Phone numbers are never shared. The phone scope is not offered — a login gives you only the id, email and profile the user approves.
Keep the client secret and tokens on your server only — never in browser JavaScript.
How it works
User clicks Login with Workly India on your website.
Your site redirects to the authorization endpoint.
User signs in on Workly India and sees the Allow / Deny screen (/oauth/consent).
Workly India redirects back to your redirect URI with a one-time code.
Your server exchanges the code at the token endpoint for an access token, refresh token and ID token.
Your server calls userinfo and logs the user in.

Register your app
On the Developer Portal home, choose Create OAuth App. Enter your app name and redirect URL to receive a client_id and (for server apps) a client_secret.
Choose type: Confidential (server websites, has a secret) or Public (single-page/mobile apps, PKCE only, no secret).
Redirect URI must match exactly (https, same path, no extra slash).

Step 3 — exchange the code for tokens

Your callback receives ?code=...&state=... . Check state matches, then call the token endpoint from your server.

Code example
curl -X POST https://jubwzelupbntbetpajqb.supabase.co/auth/v1/oauth/token \
  -u "YOUR_CLIENT_ID:YOUR_CLIENT_SECRET" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "code=CODE_FROM_CALLBACK" \
  -d "redirect_uri=https://yourwebsite.com/auth/callback" \
  -d "code_verifier=CODE_VERIFIER"

# Response
{ "access_token": "eyJ...", "token_type": "bearer", "expires_in": 3600,
  "refresh_token": "...", "id_token": "eyJ...", "scope": "openid email profile" }

Website examples
Action
Node.js / Express — full login

Complete "Login with Workly India" for a server website. Put CLIENT_ID and CLIENT_SECRET in env vars.

Code example
import express from "express";
import session from "express-session";
import crypto from "crypto";

const AUTH = "https://jubwzelupbntbetpajqb.supabase.co/auth/v1";
const REDIRECT = "https://yourwebsite.com/auth/callback";
const app = express();
app.use(session({ secret: process.env.SESSION_SECRET, resave: false, saveUninitialized: false }));
const b64url = (b) => b.toString("base64url");

app.get("/login", (req, res) => {
  const verifier = b64url(crypto.randomBytes(32));
  const state = b64url(crypto.randomBytes(16));
  req.session.oauth = { verifier, state };
  const url = new URL(AUTH + "/oauth/authorize");
  url.search = new URLSearchParams({
    response_type: "code", client_id: process.env.CLIENT_ID, redirect_uri: REDIRECT,
    scope: "openid email profile", state,
    code_challenge: b64url(crypto.createHash("sha256").update(verifier).digest()),
    code_challenge_method: "S256",
  });
  res.redirect(url.toString());
});

app.get("/auth/callback", async (req, res) => {
  const saved = req.session.oauth;
  if (!saved || req.query.state !== saved.state) return res.status(400).send("Bad state");
  if (req.query.error) return res.status(400).send("Login cancelled");
  const r = await fetch(AUTH + "/oauth/token", {
    method: "POST",
    headers: {
      "Content-Type": "application/x-www-form-urlencoded",
      Authorization: "Basic " + Buffer.from(process.env.CLIENT_ID + ":" + process.env.CLIENT_SECRET).toString("base64"),
    },
    body: new URLSearchParams({ grant_type: "authorization_code", code: req.query.code, redirect_uri: REDIRECT, code_verifier: saved.verifier }),
  });
  const tokens = await r.json();
  if (!r.ok) return res.status(400).json(tokens);
  const user = await (await fetch(AUTH + "/oauth/userinfo", { headers: { Authorization: "Bearer " + tokens.access_token } })).json();
  req.session.user = { id: user.sub, email: user.email };
  res.redirect("/");
});

app.listen(3000);

session_start();

  'clientId' => getenv('CLIENT_ID'), 'clientSecret' => getenv('CLIENT_SECRET'),

  'urlAccessToken' => 'https://jubwzelupbntbetpajqb.supabase.co/auth/v1/oauth/token',

  'scopes' => 'openid email profile', 'pkceMethod' => 'S256',
]);
if (!isset($_GET['code'])) {
  $url = $provider->getAuthorizationUrl();
  $_SESSION['state'] = $provider->getState();
  $_SESSION['pkce'] = $provider->getPkceCode();
  header('Location: ' . $url); exit;
}
if ($_GET['state'] !== $_SESSION['state']) exit('Bad state');
$provider->setPkceCode($_SESSION['pkce']);
$token = $provider->getAccessToken('authorization_code', ['code' => $_GET['code']]);
$user = $provider->getResourceOwner($token)->toArray();
echo 'Hello ' . htmlspecialchars($user['email']);

Code example
from flask import Flask, url_for, session, redirect
from authlib.integrations.flask_client import OAuth
import os
app = Flask(__name__); app.secret_key = os.environ["SESSION_SECRET"]
oauth = OAuth(app)
oauth.register("workly",
  client_id=os.environ["CLIENT_ID"], client_secret=os.environ["CLIENT_SECRET"],
  server_metadata_url="https://jubwzelupbntbetpajqb.supabase.co/auth/v1/.well-known/openid-configuration",
  client_kwargs={"scope": "openid email profile", "code_challenge_method": "S256"})

@app.route("/login")
def login():
    return oauth.workly.authorize_redirect(url_for("callback", _external=True))

@app.route("/auth/callback")
def callback():
    token = oauth.workly.authorize_access_token()
    session["user"] = token.get("userinfo")
    return redirect("/")

Verify an access token on your API

Check the JWT signature with the JWKS endpoint (Node.js, jose).

Code example
import { createRemoteJWKSet, jwtVerify } from "jose";
const JWKS = createRemoteJWKSet(new URL("https://jubwzelupbntbetpajqb.supabase.co/auth/v1/.well-known/jwks.json"));
export async function verify(token) {
  const { payload } = await jwtVerify(token, JWKS, { issuer: "https://jubwzelupbntbetpajqb.supabase.co/auth/v1" });
  return payload; // payload.sub = user id, payload.client_id = your app
}
Troubleshooting
redirect_uri mismatch — the URI in the request must exactly match a registered one.
invalid_grant — the code was already used, expired (short-lived), or code_verifier is wrong.
invalid_client — wrong client_id/secret, or a public client sent a secret.
Consent page 404 — Site URL is wrong or the app is not published.
Endless login loop — browser blocks cookies; open the authorize link in the same browser tab.
access_denied — the user pressed Deny; show a friendly message.
