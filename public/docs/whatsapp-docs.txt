Integrations

Integrate your website or automation tool with one secure endpoint after connecting your WhatsApp Business number.

Use a WhatsApp Business account and a phone number you control. Complete Meta's business, email, phone, and display-name checks when requested.
Open WhatsApp → Number in your employer account and connect the number through Meta.
Open Developer Portal → Generate New Key. Store the wfh_ key only on your server.
Create a message template and wait for Meta to mark it APPROVED. Review often completes within 24 hours but can take longer; only the returned Meta status confirms approval.
Send an approved template to your own phone, then reply from WhatsApp to open the 24-hour customer-service window.
Add your server URL under Developer Portal → Webhooks and subscribe to WhatsApp message and delivery events.

For your own Meta app, WhatsApp setup uses whatsapp_business_management and whatsapp_business_messaging; business onboarding may also require business_management. Access for other businesses depends on Meta App Review, advanced access and any required business verification. Obtain the recipient's opt-in before business-initiated messaging and honor opt-outs. Examples use dummy IDs and numbers; replace them with your own connection data and keep real credentials private.

Where to use the API
Your website's server / backend (Node, PHP, Python, etc.): call the REST endpoint with your x-api-key header.
CRM, ERP, Zapier, Make, n8n: use an HTTP request step with the same URL, header and JSON body.
Real-time incoming messages and delivery status: add a webhook in Developer Portal with the WhatsApp events.
Never put your API key in browser JavaScript or a mobile app — keep it on your server.

Multiple WhatsApp numbers
Connect as many numbers as you need from WhatsApp → Number → Add another number. One API key works for all of them.
Call list_numbers to get each number's phone_number_id.
Add "from" (phone_number_id or the number) to any request to choose the sender. If only one is connected it is used automatically; with several, the request returns 400 until you pass "from".
Templates belong to the WhatsApp Business account of the chosen number — if your numbers are in different accounts, create the template for each one.
Successful sends return "from"; incoming-message webhooks include phone_number_id so you know which number received the message.
Unknown "from" returns 404 with the message Number is not connected to your account.

JavaScript / Node.js

Run on your server only.

Code example
const API = "https://jubwzelupbntbetpajqb.supabase.co/functions/v1/whatsapp-api";

async function wa(body) {
  const res = await fetch(API, {
    method: "POST",
    headers: { "x-api-key": process.env.WORKLY_API_KEY, "Content-Type": "application/json" },
    body: JSON.stringify(body),
  });
  const data = await res.json();
  if (!data.success) throw new Error(data.error);
  return data;
}

const { numbers } = await wa({ action: "list_numbers" });
const support = numbers.find((n) => n.verified_name === "Support");

await wa({ action: "send_text", from: support.phone_number_id, to: "919876543210", text: "Hi from Support" });
await wa({ action: "send_text", from: numbers[0].phone_number_id, to: "919876543210", text: "Hi from Sales" });

Templates

Use UTILITY for transactional updates, MARKETING for promotions, and AUTHENTICATION for one-time codes. Meta may reject a template if variable examples are missing or the message has too little text around its variables. Editing an approved template can trigger a new review.

Names use lowercase letters, numbers, and underscores. Language codes must match exactly, such as en_US.
Headers can contain text, image, video, or document content; bodies can use positional variables such as {{1}}.
Every variable needs a realistic example. Check status and rejected_reason before sending.
Templates are shared at WhatsApp Business Account level. Deleting one affects every number using that account.

Messages & media

The 24-hour customer-service window starts or refreshes when the customer sends a message, not when your business sends a template. Outside that window, use an approved template with the exact language and parameters. Template approval does not replace recipient opt-in or guarantee delivery. Meta charges depend on category, destination and current pricing; Workly API quota is separate from Meta messaging charges.

Supported media types are image, video, audio, and document.
The media URL must be a public HTTPS link that Meta can download. Documents can include a filename.
Captions work with images, videos, and documents; audio messages do not accept captions.
Successful sends return a message_id. Save it to match later sent, delivered, read, or failed events.

Replies, reactions & read receipts
Every successful send returns message_id (a wamid.… id). Incoming webhooks also include message_id. Save it — replies and reactions point to it.
Reply / quote: add "reply_to":"wamid…" to send_text, send_media or send_template. The customer sees your message with the original quoted above it.
Reaction: send_reaction with message_id and one emoji. Send "emoji":"" to remove your reaction. Reactions are allowed only within 30 days of the original message and do not trigger a notification sound.
Read + typing: mark_read shows blue ticks to the customer; add "typing":true to show "typing…" for up to 25 seconds or until you reply.
Free-form replies and reactions work only within the 24-hour customer window; outside it send an approved template.
All of these also accept "from" to pick which of your numbers sends.

Inside your webhook handler, on your server.

app.post("/workly-webhook", async (req, res) => {
  res.sendStatus(200); // answer fast
  const { event, data } = req.body;
  if (event !== "whatsapp.message.received" || data.type !== "text") return;
  await wa({ action: "mark_read", message_id: data.message_id, from: data.phone_number_id, typing: true });
  await wa({ action: "send_reaction", to: data.from, message_id: data.message_id, emoji: "👍", from: data.phone_number_id });
  await wa({ action: "send_text", to: data.from, text: "Thanks! We will get back soon.", reply_to: data.message_id, from: data.phone_number_id });
});
Incoming messages & delivery status

There are two separate webhook connections: Meta sends events to Workly's configured Meta receiver; Workly forwards subscribed developer events to your server URL saved in Developer Portal → Webhooks. Do not put your developer endpoint into Meta's callback settings or replace Workly's receiver. Your server verifies Workly's X-Webhook-Signature, not Meta's upstream signature. Read stored employer conversations in WhatsApp Chat.

Add a webhook in Developer Portal → Webhooks and select whatsapp.message.received and/or whatsapp.message.status (or whatsapp.* for all). Each POST has headers X-Webhook-Event and X-Webhook-Signature (HMAC-SHA256 hex of the raw body using your endpoint secret). Reply with HTTP 200 within 8 seconds; slow requests are dropped and not retried.

data.phone_number_id tells you which of your numbers received the event. context is set when the customer quoted one of your messages; reaction is set for emoji reactions (empty emoji = removed).

Action
Verify the signature (Node.js)

Use the raw request body, not re-serialized JSON.

Code example
import crypto from "crypto";
app.post("/workly-webhook", express.raw({ type: "application/json" }), (req, res) => {
  const expected = crypto.createHmac("sha256", process.env.WORKLY_WEBHOOK_SECRET).update(req.body).digest("hex");
  const got = req.get("X-Webhook-Signature") || "";
  if (got.length !== expected.length || !crypto.timingSafeEqual(Buffer.from(got), Buffer.from(expected))) return res.sendStatus(401);
  res.sendStatus(200);
  const { event, data } = JSON.parse(req.body.toString());
  // handle event...
});
WhatsApp Business profile

Use these API actions from your website's server to read or update the customer-facing profile for any connected number.

Profile picture

JPG or PNG, under 5 MB, at least 192 × 192 pixels.

About

Required short status shown beneath the business name; up to 139 characters.

Description

Explain what the business does in up to 512 characters.

Contact details

Address, contact email, and up to two full website links.

Business category

Choose the Meta category that best represents the business.

Account health

Review display-name status, verification, quality rating, messaging limit, and throughput.

Call get_profile first. Add from to select a number; if only one is connected it is used automatically; with several, the request returns 400 until you pass from.
update_profile requires about. Omitted optional text fields are cleared, so send the complete profile you want to keep.
Profile pictures must be JPG or PNG, under 5 MB and at least 192 × 192 pixels. Send one as a base64 data URL in profile_picture.
Never expose the wfh_ key in browser code. Your website form must submit to your own server, which then calls this API.

Onboarding & Embedded Signup

Onboard many businesses, each with its own WhatsApp number connected through Embedded Signup. All calls are POST to one URL with the business's wfh_ key in the x-api-key header.

Embedded Signup first: a business can send only after its number is connected through the Facebook connect flow. Manual tokens are a backup, not the default.
One business = one key: each business uses its own wfh_ API key. Keys never see another business's numbers, templates or chats.
Add from (phone_number_id or the number digits) to any send call to choose the sender; without it, the business's default number is used.

Embedded Signup — connect a WhatsApp number
Every business connects its own number with the Facebook (Meta) connect button — no manual tokens. Open Employer → WhatsApp → Number and click 'Connect with Facebook'.

Code example
What happens behind the button:
1. Facebook login opens with the app's Embedded Signup configuration
2. Business picks (or creates) a WhatsApp Business account and adds a number
3. Meta returns a code + waba_id + phone_number_id to the app
4. The app exchanges the code for a token, subscribes the app to the
   WhatsApp account, registers the number, and stores everything
   under that business — server-side only

Result: the number shows as Connected with its quality rating,
and all API calls for that business use it automatically.

Onboard many businesses (multi-customer)
Each customer/business has its own company profile and its own connected number(s). Onboarding a new customer is always the same two steps: create their account, then they connect WhatsApp with Embedded Signup. Their messages, templates and chats stay fully separate from every other business.

Code example
Per business:
- Own company profile  → own API key (wfh_...)
- Own WhatsApp number(s) via Embedded Signup
- Own templates, chats, campaigns and usage quota

Connect WhatsApp for your users

Have your own users? Put a Connect WhatsApp button on your website. Each user connects their own WhatsApp Business number, and you send from it with your same wfh_ key. Each user's number, templates and chats stay separate.

Sub-accounts are visible only to your key. Other developers get "Sub-account not found".
All sub-account calls count against your own API quota and appear in your API Logs.
Meta tokens stay on Workly India servers. You never see or store them.
Meta requirement: connecting many outside businesses needs Workly India to be a verified Meta Tech Provider. Until that approval is complete, Meta may limit who can finish the connect step.

Action
2. Get a connect link and show your Connect WhatsApp button

The link opens a Workly India page with Connect with Facebook. It works once and expires after 1 hour, so create it when the user clicks your button. return_url must be https.

Code example
// Your server (Node.js / Express)
app.post("/connect-whatsapp", async (req, res) => {
  const r = await fetch("https://jubwzelupbntbetpajqb.supabase.co/functions/v1/whatsapp-api", {

Bulk / Campaign messaging

Send one approved template to many contacts by looping over your CSV list and calling the API once per number.

How bulk sending works
A campaign = one approved template sent to many contacts. There is one send_template call per recipient: read your contact list (CSV, sheet or database) and call the API once per number with a small delay. Recipients who have not messaged you in 24 hours must get a template; free-form text works only inside the 24-hour window.

Code example
CSV file (contacts.csv):
phone,name
919876543210,Rahul
919123456789,Priya

For each row → one API call:
POST https://jubwzelupbntbetpajqb.supabase.co/functions/v1/whatsapp-api
{ "action": "send_template", "to": "<phone>", "template_name": "...", "language": "en_US", "body_params": ["<name>"] }

Bulk send with JavaScript (CSV upload)
Reads a CSV file, then sends the template to every row with a 1 second gap so Meta rate limits are respected.

Code example
import fs from "fs";

const API = "https://jubwzelupbntbetpajqb.supabase.co/functions/v1/whatsapp-api";
const KEY = process.env.WORKLY_API_KEY;

async function sendTemplate(to, name) {
  const r = await fetch(API, {
    method: "POST",
    headers: { "x-api-key": KEY, "Content-Type": "application/json" },
    body: JSON.stringify({
      action: "send_template", to,
      template_name: "offer_october", language: "en",
      body_params: [name],
    }),
  });
  const j = await r.json();
  if (!j.success) throw new Error(`${to}: ${j.error}`);
  return j;
}

const rows = fs.readFileSync("contacts.csv", "utf8").trim().split("\n").slice(1);
for (const line of rows) {
  const [phone, name] = line.split(",");
  try { await sendTemplate(phone.trim(), name.trim()); console.log("sent", phone); }
  catch (e) { console.error("failed", e.message); }
  await new Promise((r) => setTimeout(r, 1000)); // 1 msg / second
}

Bulk send with Python (CSV upload)
Same flow with requests and the csv module.

Code example
import csv, os, time, requests

API = "https://jubwzelupbntbetpajqb.supabase.co/functions/v1/whatsapp-api"
H = {"x-api-key": os.environ["WORKLY_API_KEY"]}

def send_template(to, name):
    j = requests.post(API, json={
        "action": "send_template", "to": to,
        "template_name": "offer_october", "language": "en",
        "body_params": [name],
    }, headers=H).json()
    if not j.get("success"):
        raise Exception(f"{to}: {j.get('error')}")
    return j

with open("contacts.csv") as f:
    for row in csv.DictReader(f):
        try:
            send_template(row["phone"].strip(), row["name"].strip())
            print("sent", row["phone"])
        except Exception as e:
            print("failed", e)
        time.sleep(1)  # 1 msg / second

Rules to avoid blocks
Approved templates only: Bulk messages to users who have not messaged you in 24 hours must use a Meta-approved template. Free-form text works only inside the 24-hour window.
Pace your sends: Keep about 1 message per second per number. New numbers start with a daily limit (e.g. 250 business-initiated conversations) that Meta raises automatically with good quality.
Phone format: Digits only, with country code and no +: 919876543210.
Opt-out: Stop messaging any user who asks to stop, or Meta will lower your quality rating and may restrict the number.

Rate limits & messaging tiers

Workly India enforces the same tiered limits Meta does, so one customer's heavy or low-quality sending can never slow down or block anyone else on the platform. Limits are enforced per API key, per sub-account, and per phone number.

Three scopes are checked on every send: Your API key as a whole, each sub-account, and each phone number each have their own counter. The first scope to reach its cap blocks the send — exactly how Meta enforces limits.
24-hour messaging tier: Each number has a Meta messaging tier: 250, 2,000, 10,000, 100,000 or Unlimited business-initiated conversations per 24 hours. New numbers start at 250; Meta lifts it to 2,000 after business verification, then raises it automatically (10,000, 100,000, Unlimited) as quality and unique-customer volume grow. The limit is shared by every number in your business portfolio. The window is rolling — it resets 24 hours after the first message of the current window.
Burst limit: At most 20 messages per second per scope. If you burst faster, the API tells you to retry after 1 second.
Quality-based throttling: If Meta drops a number's quality rating to YELLOW, its limit is automatically halved; RED quarters it (minimum 50). When Meta restores GREEN, the full limit applies again — no action needed from you.
Check your usage anytime: Call {"action":"status"} — the whatsapp_limits field shows your tier, used_24h, remaining_24h and resets_at, so you never need to contact support to know where you stand.
When a limit is hit: The send returns success:false with error, limit, used, remaining, resets_at and retry_after_seconds. Queue the message and retry after retry_after_seconds — do not retry in a tight loop.

Troubleshooting

Every response is JSON. Success: {"success":true,...}. Failure: {"success":false,"error":"...","meta_code":131047} (meta_code only for WhatsApp errors).

400 — Invalid request
A field is missing or wrong; see details. Also returned for WhatsApp errors with meta_code.
401 — API key problem
Missing, invalid, inactive or expired x-api-key (must start with wfh_).
402 — Subscription inactive
Activate an API plan in Developer Portal.
403 — No company
The key's account has no company profile. Create the company profile first.
404 — Number not connected
The from value doesn't match any of your numbers. Call list_numbers.
409 — WhatsApp not connected
Connect and verify a number on the employer WhatsApp page before sending.
429 — WhatsApp limit reached
The 24-hour tier limit or the per-second burst limit was hit for your API key, sub-account or number. The response includes resets_at and retry_after_seconds — retry after that. See Rate limits & tiers.
502 — Meta unavailable
Temporary WhatsApp outage. Retry after a short wait.
meta_code 131047 — 24-hour window expired
Send an approved template instead of text, media, reply or reaction.
meta_code 131026 — Message undeliverable
Recipient isn't on WhatsApp, or the number/country code is wrong.
meta_code 132001 — Template not found
Check exact template name and language code, and that it's APPROVED on the same number's account.
meta_code 132000 — Parameter count mismatch
body_params must match the number of {{n}} variables exactly.
meta_code 131056 — Too many messages
Rate limit to the same recipient. Slow down and retry.
meta_code 131009 — Invalid parameter
Often a wrong reply_to/message_id or a non-public media URL.
